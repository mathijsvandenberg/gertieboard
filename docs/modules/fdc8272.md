# fdc8272

Source: [`fdc8272.vhd`](../../fdc8272.vhd) · Instance `fdc1` · Clock `c0` (8.33 MHz)

A µPD765 / 8272-compatible floppy controller. There is no physical floppy drive:
the controller presents the standard register interface to software, and fetches
the actual sector data over a **1 Mbaud serial link to a host program**.

That same link is how the BIOS image itself arrives at boot.

## Generic map

```vhdl
fdc1 : fdc8272 GENERIC MAP (UART_CLK_HZ => 50000000, BAUD => 1000000)
               PORT MAP    (CLK => n_cpuclk, CLK_UART => n_c3, ...)
```

**The UART has its own clock, and that is the whole point.** `CLK_UART` is `c3` —
50 MHz, fixed, unaffected by the [speed step](clkgen-pll.md#the-ladder). The command
engine stays on the bus clock; only the bit timing moved.

| `BAUD` | `BAUD_DIV` | error | note |
|---|---|---|---|
| 1,000,000 | 50 | **0 %** | current setting |
| 2,000,000 | 25 | **0 %** | also exactly FTDI's 3 MHz ÷ 1.5 |
| 2,500,000 | 20 | 0 % | an FTDI cannot make this — ÷1.2 is not representable |

> ⚠️ It used to divide the **bus** clock, which was survivable only while that clock was
> a constant. Once the speed became a register, `BAUD_DIV` had to be re-derived per step,
> and an integer divide of 5 / 6.25 / 7.143 / 8.333 / 10 / 12.5 / 16.667 MHz never lands
> on the same number twice — the best table available was **+4.2 % at the step the
> machine boots at**. 8N1 tolerates about 5 %, so every BIOS transfer ran near the edge
> of the envelope, and an intermittent stall just after "BIOS fetched" is what living
> there looks like.
>
> It also could not scale. At 2 Mbaud a 6.25 MHz bus clock needs a divisor of 3.125 and
> gets 3 — 25 % out. At 3 Mbaud a 5 MHz bus clock has 1.67 clocks per bit and cannot
> sample the line at all. Going faster *required* leaving the CPU clock behind.
>
> The old failure was the same shape from the other end: with the original entity
> defaults (50 MHz / 115200) the link ran at 5e6/434 = 11.5 kbaud — working, but at a
> fraction of the intended rate.

`BAUD` is one setting in two places: change it here **and** on the host, because nothing
checks that they agree.

### Crossing between the two clocks

The controller's interface is unchanged — `tx_start` is still a one-shot, `tx_busy` a
level, `rx_valid` a one-clock pulse — so the command engine did not have to be touched.
Underneath, three toggles carry it across, because a one-cycle 50 MHz pulse is 20 ns and
a bus clock can be 200 ns: a pulse would simply be missed.

`tx_busy` is raised by the **CLK-side** shim the moment `tx_start` is seen, not by
waiting for the UART's own busy to come back through the synchroniser. That wait is two
bus clocks, and during it the controller's guard (`tx_busy = '0' AND tx_start = '0'`)
would be satisfied again and it would push a second byte on top of the first.

A side benefit: at 50 MHz the receiver takes 50 samples per bit where the bus-clock
version had 5 at the slowest step, so the mid-bit sampling point is placed to within 2 %
of a bit instead of 20 %.

|---|---|---|---|
| `CLK` | IN | 1 | 8.33 MHz (`c0`) — also the UART reference |
| `RESET` | IN | 1 | Active high |

| Port | Dir | Width | Purpose |

## Addresses

| Port | Access | Register |
|---|---|---|
| `0x3F2` | W | **DOR** — Digital Output Register: motor enable, drive select, `/reset`, DMA enable |
| `0x3F4` | R | **MSR** — Main Status Register: `RQM` (bit 7), `DIO` (bit 6), `CB` (bit 4) |
| `0x3F5` | R/W | **Data / FIFO** — command bytes, result bytes, and PIO data |
| `0x3F7` | R | **DIR** — Digital Input Register |
| `0x3F7` | W | **CCR** — Configuration Control Register |

`0x3F0`, `0x3F1`, `0x3F3` and `0x3F6` are not decoded.

## Host protocol

The controller speaks a deliberately tiny protocol so the host side stays simple:

```
READ :  FPGA -> host : 0x33 0x01 C H R
        host -> FPGA : <512 data bytes>

WRITE:  FPGA -> host : 0x33 0x02 C H R <512 bytes>
        host -> FPGA : 0x06            (ACK)
```

`0x33` is the preamble; `C`, `H`, `R` are cylinder, head and sector.

### The reserved BIOS cylinder

**`C = 0xFF` is not a real cylinder.** A read of it means "serve me the BIOS image",
and the host returns bytes from the BIOS file at offset `(R - 1) × 512`. That is how
the bootloader pulls a 64 KB BIOS across at reset — 128 sectors of a cylinder that
does not exist.

Everything else is served from the floppy image using the geometry the host detects
from the image size.

## Transfer modes

| Mode | Used by | How |
|---|---|---|
| **DMA** | the BIOS | `DRQ`/`DACK` with the 8237; data moves through `busdecode`'s HLDA mux |
| **non-DMA (PIO)** | the bootloader | `Specify` with `ND = 1`; bytes move through the `0x3F5` FIFO, polling `MSR.RQM` |

The bootloader uses PIO deliberately: it then needs no 8237 programming at all,
which keeps a small boot ROM feasible.

## Implemented commands

Enough of the 8272 command set for the BIOS and DOS: `Specify`, `Recalibrate`,
`Seek`, `Sense Interrupt Status`, `Sense Drive Status`, `Read Data`, `Write Data`,
and the result phases they need. A 512-byte sector buffer sits inside the module.
