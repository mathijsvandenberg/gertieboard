# ppi8255

Source: [`ppi8255.vhd`](../../ppi8255.vhd) · Instance `ppi1` · Clock `c0` (5 MHz)

A simplified Intel 8255 PPI as wired on the IBM 5160 (XT) motherboard. Only the
functions the XT actually used are implemented, and the port directions are
hard-wired to the XT setup (A in, B out, C in).

## Ports

### Bus

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `CLK` | IN | 1 | 5 MHz (`c0`) |
| `RESET` | IN | 1 | Active high |
| `ADDR` | IN | 16 | I/O address |
| `DATA` | IN | 8 | CPU write data |
| `DATA_OUT` | OUT | 8 | Read data, `'Z'` when not addressed |
| `RD` | IN | 1 | I/O read strobe |
| `WR` | IN | 1 | I/O write strobe |

### Port A — keyboard input

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `KBD_DATA` | IN | 8 | Scancode from [`ps2_kbd_ppi`](ps2_kbd_ppi.md) (the XT's 74LS322 shifter) |

### Port B — outputs

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `TIMER2_GATE` | OUT | 1 | PB0 → 8253 `G2` (speaker timer gate) |
| `SPEAKER_DATA` | OUT | 1 | PB1 → AND'd with `TIMER2_OUT` to drive the speaker |
| `ENABLE_PARITY_N` | OUT | 1 | PB4 — **`OPEN`** in the top level |
| `ENABLE_IOCHK_N` | OUT | 1 | PB5 — **`OPEN`** |
| `KBD_CLOCK_HOLD` | OUT | 1 | PB6 — **`OPEN`** |
| `KBD_CLEAR` | OUT | 1 | PB7 → keyboard clear/acknowledge line |

### Port C — status inputs

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `TIMER2_OUT` | IN | 1 | PC5 — read-back of 8253 counter 2 |
| `IOCHK_N` | IN | 1 | PC6 — I/O channel check (NMI source); tied `'0'` |
| `PARITY_ERR_N` | IN | 1 | PC7 — RAM parity error (NMI source); tied `'0'` |

## Addresses

Decoded as `ADDR(15 downto 2) = "00000000011000"`, i.e. `0x60`–`0x63`.

| Port | Access | Function |
|---|---|---|
| `0x60` | R | Port A — keyboard scancode |
| `0x61` | R/W | Port B — speaker and keyboard control |
| `0x62` | R | Port C — SW1 DIP switches (nibble-selected by PB3) and NMI status |
| `0x63` | W | Control word. The BIOS writes `0x99`: mode 0, A in, B out, C in |

## Speaker

Two bits gate the tone, exactly as on a real XT:

```
PB0 (TIMER2_GATE)  -> opens the 8253 counter-2 gate
PB1 (SPEAKER_DATA) -> AND'd with the counter's output
```

The AND happens in the top level:

```vhdl
BUZ <= '0' WHEN SPEAKER_MUTE = '1' ELSE (n_speaker_data AND n_out2);
```

Software drives it the standard way: program counter 2 for the tone, then set
`0x61` bits 0 and 1.

> `SPEAKER_MUTE` is a constant in [`gertieboard.vhdl`](../../gertieboard.vhdl) — set
> it to `'1'` to silence the buzzer without touching anything else.

## SW1 DIP switches

Read through port C, nibble-selected by PB3. There are no physical switches; the
value software sees is a constant:

```vhdl
constant SW1 : std_logic_vector(7 downto 0) := x"6C";
```

Decoded LSB-first, that means:

| Switches | Setting | Value |
|---|---|---|
| SW1-1 | POST manufacturing loop | 0 = normal boot |
| SW1-2 | 8087 coprocessor present | 0 = none |
| SW1-3..4 | motherboard RAM banks | `11` = all four populated |
| SW1-5..6 | initial display | `10` = colour 80×25 (CGA) |
| SW1-7..8 | floppy drive count | `01` = 2 drives |

On a real board the switches are inverted by a buffer; this constant is already the
value the BIOS reads, so no inversion is applied.

## Keyboard acknowledge

PB7 (`KBD_CLEAR`) is the XT's read-and-clear line. The BIOS's `INT 09h` pulses it
after reading a scancode, and [`ps2_kbd_ppi`](ps2_kbd_ppi.md) waits for that pulse
before presenting the next byte — with a fallback for AT-style software that never
sends it.

## Notes

- The module's header describes `RD`/`WR` as active **high**; the top level wires
  them to the active-low `n_io_rd`/`n_io_wr` nets and the module inverts internally
  to `rd_act`/`wr_act`.
- The mode register is accepted but ignored — directions are fixed to the XT layout.
- Bit set/reset of port C is a no-op, since port C is all inputs on the XT.
- Cassette data in (PC4 on the 5150) is unused on the 5160 and tied `'0'`.
