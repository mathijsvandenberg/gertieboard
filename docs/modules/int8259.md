# int8259

Source: [`int8259.vhd`](../../int8259.vhd) · Instance `int1` · Clock `c0` (5 MHz)

An 8259A Programmable Interrupt Controller in the single-master configuration used
by the IBM PC/XT.

## Ports

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `CLK` | IN | 1 | 5 MHz (`c0`) |
| `RESET` | IN | 1 | Active high |
| `DATA` | IN | 8 | CPU write data |
| `DATAOUT` | INOUT | 8 | Read data, tri-state |
| `ADDR` | IN | 16 | I/O address |
| `RD` | IN | 1 | I/O read strobe, active low |
| `WR` | IN | 1 | I/O write strobe, active low |
| `INT` | OUT | 1 | → `CPU_INTR` — interrupt request to the CPU |
| `INTA` | IN | 1 | ← `CPU_INTA` — interrupt acknowledge |
| `IRQ0` | IN | 1 | ← `timer8253.OUT0` — system tick |
| `IRQ1` | IN | 1 | ← `ps2_kbd_ppi.irq1` — keyboard |
| `IRQ2` | IN | 1 | tied `'0'` — unused |
| `IRQ6` | IN | 1 | ← `fdc8272.IRQ` — floppy |

Only the four request lines the machine actually uses are brought out.

## Addresses

Decoded as `ADDR(15 downto 1) = "000000000010000"`, with `A0 = ADDR(0)`:

| Port | Access | Function |
|---|---|---|
| `0x20` | W | ICW1 (init sequence start), OCW2 (EOI), OCW3 (read-register select) |
| `0x20` | R | IRR or ISR, depending on the last OCW3 |
| `0x21` | W | ICW2 / ICW3 / ICW4 during initialisation; OCW1 (IMR) afterwards |
| `0x21` | R | IMR |

## Implemented behaviour

- Full initialisation sequence: **ICW1 → ICW2 → [ICW3] → [ICW4]**
- Programmable vector base from ICW2 — the XT BIOS programs `0x08`, so IRQ0 becomes
  `INT 08h`, IRQ1 `INT 09h`, IRQ6 `INT 0Eh`
- **IRR / ISR / IMR** with fully-nested priority resolution, IR0 highest
- Edge- or level-triggered request capture, selected by LTIM in ICW1
- Two-pulse 8086/8088-mode interrupt acknowledge, with the vector on pulse 2
- OCW1 mask register at `0x21`, correct polarity (**1 = masked**)
- OCW2 non-specific and specific EOI at `0x20`
- OCW3 read-register select, so software can read IRR or ISR back from `0x20`

## Interrupt sequence

```
IRQn asserted ──> IRR bit set ──> priority resolve against ISR/IMR
              ──> INT asserted ──> CPU responds with INTA pulse 1
              ──> INTA pulse 2  ──> vector placed on the data bus, ISR bit set
              ──> handler runs, writes EOI to 0x20 ──> ISR bit cleared
```

Because the controller is edge-capable, IRQ sources here present a clean `0 → 1`
transition per event. `ps2_kbd_ppi` is explicit about this: it raises `irq1` once per
scancode and drops it on acknowledge, which suits edge-triggered capture.

## Vector mapping as used

| Line | Source | Vector | BIOS handler |
|---|---|---|---|
| IRQ0 | 8253 counter 0 | `INT 08h` | timer tick, chains `INT 1Ch` |
| IRQ1 | keyboard | `INT 09h` | scancode → keyboard buffer |
| IRQ6 | floppy | `INT 0Eh` | floppy operation complete |
