# dma8237

Source: [`dma8237.vhd`](../../dma8237.vhd) · Instance `dma1` · Clock `c0` (8.33 MHz)

An 8237A DMA controller: the full programmer's-view register set, plus a real
single-transfer bus master so the floppy controller can move bytes to and from
PSRAM without the CPU.

## Ports

### Bus

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `CLK` | IN | 1 | 8.33 MHz (`c0`) |
| `RESET` | IN | 1 | Active high |
| `IO_ADDR` | IN | 16 | I/O address |
| `IO_RD` / `IO_WR` | IN | 1 | I/O strobes, active low |
| `DATAIN` | IN | 8 | CPU write data |
| `DATAOUT` | INOUT | 8 | Register read-back, tri-state |

### Bus mastering

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `HRQ` | OUT | 1 | → `CPU_HLD` — request the bus |
| `HLDA` | IN | 1 | ← `CPU_HLDA` — bus granted |
| `DMA_ADDR` | OUT | 16 | Current transfer address (low 16 bits) |
| `DMA_MEMR` / `DMA_MEMW` | OUT | 1 | Memory strobes, active low |
| `DMA_IOR` / `DMA_IOW` | OUT | 1 | I/O strobes — **`OPEN`** in the top level |
| `RAM_READY` | IN | 1 | ← `mem_hybrid` — wait for the memory cycle |

### Device handshake

| Port | Dir | Width | Purpose |
|---|---|---|---|
| `DREQ` | IN | 1 | ← `fdc8272.DRQ` — channel 2 request |
| `DACK` | OUT | 1 | → `fdc8272.DACK` — channel 2 acknowledge |
| `TC` | OUT | 1 | → `fdc8272.TC` — terminal count, asserted on the final byte |

## Addresses

Decoded as `IO_ADDR(15 downto 4) = 0x000`, i.e. **`0x00`–`0x0F`**.

| Ports | Function |
|---|---|
| `0x00`–`0x07` | Channel 0–3 address and count pairs, with the shared byte-pointer flip-flop |
| `0x08` | Command / status |
| `0x09` | Request |
| `0x0A` | Single mask |
| `0x0B` | Mode |
| `0x0C` | Clear byte pointer |
| `0x0D` | Master clear |
| `0x0E`–`0x0F` | Clear mask / write all mask |

The **page register is not here** — the upper four address bits live at I/O `0x81`
inside [`busdecode`](busdecode.md), matching the XT's separate 74LS612.

## Transfer sequence

```
DREQ(n) (or a software request)
    -> HRQ asserted        -> CPU HOLD
    -> CPU grants (HLDA)
    -> engine drives DMA_ADDR + DACK(n) + the memory strobe for ONE byte
    -> waits for RAM_READY
    -> advances the address, decrements the count
    -> releases HRQ  (single-transfer mode)
    -> TC asserted on the final byte
```

Direction comes from `mode_reg(ch)(3:2)`:

| Value | Meaning | Strobes |
|---|---|---|
| `01` | write-to-memory (floppy **read**) | `IOR` + `MEMW` |
| other | read-from-memory (floppy **write**) | `MEMR` + `IOW` |

## Data does not flow through this module

Worth stating plainly, because it is unusual: `dma8237` **only sequences** the
transfer. The byte itself moves between the FDC and PSRAM through
[`busdecode`](busdecode.md)'s `HLDA` mux:

```
floppy read :  fdc8272.DMA_DOUT -> busdecode.DMA_DOUT -> DATA_OUT -> mem_hybrid
floppy write:  mem_hybrid.DATAOUT -> fdc8272.DMA_DIN
```

That is why `DMA_IOR`/`DMA_IOW` can be left `OPEN`: the FDC knows from `DACK` and the
memory strobe when to present or latch a byte.

## Usage in practice

Only **channel 2** is used, by the floppy controller, which is the same assignment a
real XT used. The BIOS programs the address, count and page register before each
floppy operation.

The bootloader deliberately avoids DMA entirely — it drives the FDC in non-DMA
(PIO) mode so it needs no 8237 setup at all. See [boot flow](../boot.md).
